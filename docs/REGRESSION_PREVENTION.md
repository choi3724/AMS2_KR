# 기존 수정사항의 누락 방지

## 원인과 기준

0.83에서 게임 업데이트에 맞춰 순정 메뉴를 다시 만들면서, 예전에 바꾼
폰트 이외의 필드와 메뉴 안의 직접 문자열이 빠졌다. 번역표가 정상이어도
도움말의 표시 설정·문구 연결이 되돌아가면 빈칸이나 영어가 표시될 수 있다.

공개 0.83.3을 보존 기준으로 사용한다. 기준은
`tools/repository/regressions/baseline-0.83.3.json`에 Git으로 관리한다.
배포 ZIP의 검증된 해시·커밋과 패키지 자산 470개, 호환성 데이터 9개의 해시를
기록한다. 개인 PC의 현재 게임 파일이나 마지막으로 생성한 후보를 자동으로
새 기준으로 채택하지 않는다. 기준 파일은 완성된 모든 기능의 실제 화면 검증을
의미하지 않는다.

## 기존 수정 목록

| 항목 | 보존 대상과 검사 | 실제 확인의 범위 |
|---|---|---|
| 첫 메뉴 한글과 글꼴 | 메뉴·폰트·텍스처 파일, 일반/VR의 메뉴 재적용 | 다른 PC 전체 별표 제보의 원인은 별도 미확인 |
| 예선 랩 수/주행 횟수와 새 번역 | 9개 TDB 전체 파일, 기존 번역 재병합 검사 | 화면별 육안 확인 별도 |
| 헤일로 기둥 숨기기 도움말 | 두 빌드·두 메뉴의 표시 바이트와 번역 참조를 독립 검사 | 도움말 레이아웃 확인 별도 |
| HUD 베타 도움말 | 두 빌드 메뉴의 한국어 직접 문자열을 독립 검사 | 줄바꿈·잘림 확인 별도 |
| 리플레이 저장 안내 | 수정된 game.tdb를 이전 상태로 되돌리지 못하게 검사 | 멀티플레이 저장 안내 확인 대기 |
| 세이프티 카 띄어쓰기 | 기존 번역 파일 보존 | 이전에 저장한 리플레이의 이름까지 바꾸지 않음 |
| 피트 제한 속도 표시 | 수정된 메뉴/BGUI 파일 보존 | 과거 사용자 확인, 새 게임 빌드에서 재확인 필요 |
| ERS 한글·계기판 | 차량 BGUI·폰트·HUD 델타·재적용 리소스 보존 | 확인 차량/모드 외 전체 차량 검증을 의미하지 않음 |
| 실행/업데이트/복구 | 일반·VR 런처 메뉴 재적용, 별도의 런처 및 설치 수명주기 검사 | 자동 설치 후 게임 재실행·실제 VR 확인 별도 |

## 자동 차단

`Build-Release0831.py`의 0.83.3 이상 패키지 조립 마지막에
`release_regressions.verify`가 자동으로 실행된다. 버전 기본값도 0.83.3이다.
0.83.1/0.83.2의 명시적 역사 재현은 당시 누락까지 재현하므로 새 보존 기준을
소급 적용하지 않는다. 새 버전을 추가할 때 이 분기를 낮추거나 건너뛰지 않는다.

1. 패키지의 번역·메뉴·폰트·차량 HUD·런타임과 호환성 리소스를 기준과 대조한다.
   파일 누락, 예상하지 않은 추가, 이전 내용으로의 변경을 모두 보고한다.
2. 두 게임 빌드의 매니페스트에 필요한 파일이 전부 있는지, 중복이 없는지,
   실제 파일 크기와 해시가 일치하는지 검사한다. 후보가 자체 생성한 매니페스트만
   맞는 것으로 성공을 판정하지 않는다.
3. 헤일로 도움말과 HUD 베타 번역을 독립 검사한다. 메뉴 파일 변경을 의도적으로
   기록한 경우에도 이 조건은 통과해야 한다.
4. 버전마다 바뀌는 설치 프로그램과 일반·VR 런처는 고정 파일 해시 대신
   어셈블리 버전 및 각 바이너리에 들어 있는 실제 메뉴 재적용 코드를 검사한다.
   2빌드 × 4메뉴 × 3바이너리 결과가 검증된 후보와 같아야 한다.
   게임이나 설치 프로그램의 진입점은 실행하지 않는다.

실패하면 명령은 오류로 종료하고 패키지 상태를 `BLOCKED_REGRESSION`으로 기록한다.
`manifest/regression-report.json`에서 달라진 파일과 기대/실제 해시를 확인한다.
실패한 중간 폴더를 ZIP으로 묶어 배포하지 않는다. 통과 상태는
`REGRESSION_PASS_AWAITING_LIFECYCLE`이며 설치·복구 검증을 대신하지 않는다.

## 게임 업데이트 또는 새 수정 작업 순서

1. Steam 빌드와 원본 해시를 확인하고 새 작업 폴더에 추출한다.
2. 기존 폰트 교체, 번역 재병합, 도움말 표시/참조, 직접 문자열, ERS 수정을 모두
   적용한다. 게임 빌드 번호만 보고 알 수 없는 파일을 덮어쓰지 않는다.
3. 새 패키지를 조립해 보존 검사 보고서를 읽는다. 기존 수정이 빠진 경우는
   재적용 코드를 고친다. 보고서에서 실패했다는 이유만으로 기준 해시를 갱신하지 않는다.
4. 의도한 변경만 기준 파일의 `reviewed_changes`에 정확한 대상과 이전/새 SHA256,
   변경 이유(`reason`), 검증 결과(`validation`)를 기록한다. 범용 와일드카드나
   검사 생략 옵션은 없다. 삭제나 큰 구조 개편은 보존 기준 자체와 검사 범위를
   검토해야 하며, 자동 승인하지 않는다. 이 기록은 개발 검토 기록이며 사용자의
   반복 승인 절차를 추가하는 것이 아니다.
5. 새 버그를 고치면 독립적인 기대 결과와 재발시키는 실패 사례를 함께 추가한다.
   이후 `Test-TranslationRefresh.py`, `Test-ReleaseRegressions.py`, 런처 검사,
   두 빌드의 `Test-LegacyCompatibility.py`를 변경 범위에 맞게 실행한다.
6. 실제 게임에서 수정 화면과 정상/VR 실행 등 관련 항목을 확인하고, 릴리즈 요청이
   있을 때만 커밋·버전/태그·게시·공개 다운로드 검증을 진행한다.

재발 차단 검사는 다음과 같이 게임 파일을 건드리지 않고 실행할 수 있다.

```powershell
python -B tools/repository/release_regressions.py --package <패키지> --compatibility <호환성-빌드> --version 0.83.3 --report <외부-경로>/regression-report.json
python -B tools/repository/Test-ReleaseRegressions.py --package <0.83.3-패키지> --compatibility <0.83.3-호환성-빌드> --output <새-외부-테스트-폴더>
```

후자의 회귀 테스트는 공개 0.83.3 및 이전 0.83.2 런처를 사용하는 고정 테스트이다.
다음 버전의 설치 검증에는 해당 버전의 패키지/호환성 경로를 첫 명령에 전달한다.

## 아직 해결된 것으로 기록하면 안 되는 항목

리플레이 타이머 잘림, 다른 PC 전체 별표 증상, FCY/오디오/카메라 관련 과거 메뉴
차이 등은 별도 검토 대상이다. 과거 0.82 메뉴를 통째로 복원하면 리플레이 안내에
잘못된 키 연결을 되살릴 수 있다. 외부 `analysis/qualifying-20260913/legacy-nonfont-audit.json`
및 당시 점검 문서를 근거로 항목별 조사한다. 이번 장치는 현재까지 반영된 수정이
조용히 빠지는 일을 막으며 모든 미래 게임 업데이트의 자동 호환을 보장하지 않는다.
