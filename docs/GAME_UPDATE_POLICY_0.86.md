## 공통 처리 순서

1. 활성 설치 기록과 중단된 트랜잭션을 확인한다.
2. 모든 관리 파일을 읽고 현재 파일에서 후보를 만든다.
3. BGUI는 폰트 경로와 검증된 도움말·표시 항목만 바꾸고, 역변환으로 나머지 바이트 보존을 확인한다.
4. 두 HUD BFF는 대상 내부 항목을 다시 추출·패치·삽입하고 다른 항목의 메타데이터와 payload가 같은지 확인한다.
5. CM 공유 파일은 고정 위치 대신 유일한 변경 영역을 찾고, CM 상태와 파일 시간을 보존한다.
6. 필수 실패를 모두 수집한 뒤 하나라도 있으면 쓰지 않는다.
7. 후보 생성 후 파일이나 CM 상태가 달라지지 않았는지 확인하고, 백업한 다음 반영한다.
8. 실패하면 이번 작업의 게임 파일·백업·설치 기록을 작업 전 상태로 되돌린다. 강제 중단 기록은 다음 실행에서 먼저 복구한다.
9. 실행 가능 상태를 별도로 확인한 뒤 일반 또는 VR Steam 실행 요청을 한 번만 보낸다.

## 검증 증거

- 규칙 생성: 98개 BGUI 원본·패치 쌍 역검증 PASS
- 배포 회귀: 기존 번역, 폰트, 도움말, ERS, HUD 자산과 두 빌드 메뉴 재적용 PASS
- 적응형 정책: 10개 설치·재적용·부분 실패·무변경·제거 시나리오 PASS
- CM: 12개 재생성·무관 변경 보존·충돌·롤백·중단 복구 시나리오 PASS
- 현재 PC: 빌드 25391793에서 100개 항목 재적용, 0.86 승계, 467개 상태 검증 및 반복 검사 PASS

실게임 화면의 한글 표출과 VR HMD 화면은 사용자가 실행해 확인해야 한다. 자동 검증은 Steam 요청 인수와 설치 파일 상태까지 확인한다.
