# v0.87 공통 업그레이드 인계

## 기준과 원인

기준은 공개 v0.86, 커밋 `fe671c3d93306fce773ddc36330605f116585868`이다. 기존 작업과 0.86 소스는 보존하고 `installer/0.87`에 구현했다.

빌드·해시와 파일 형식별 적용 정책은 [0.86 정책 조사](GAME_UPDATE_POLICY_0.86.md)를 유지한다. 이번 릴리스는 그 위에 구버전 소유권·원본 인계와 외부 업그레이드 트랜잭션을 추가한다.

제보 ZIP `AMS2-Korean-Beta07-Diagnostic-20260919-203356.zip`에는 설치 기록 원문과 실제 이전 런처가 없었다. 따라서 고객 디스크의 완전 복제가 아니라, 공식 0.84 배포 파일과 대표 설치 기록으로 재현했다. 진단에는 선행 재적용 1개 이후 일반·VR 런처 충돌, 재시도 동일 실패가 기록되어 있다.

0.86의 created 파일 사전 검사는 새 패키지 해시와 AllowedBefore만 허용했다. 이전 소유권을 인계하는 단계보다 먼저 실행되어 공식 0.84 런처도 차단했다. 실제 0.84 런처 해시는 해당 허용 목록에 없다. 0.86 기준 CLI와 공식 패키지에서도 두 런처 충돌을 재현한다. 이번 변경은 특정 두 파일 또는 버전 조합의 예외가 아니다.

## 공통 구조

`UpgradeOwnership`는 알려진 백업 컨테이너 안의 모든 설치 기록을 읽는다. 폴더 이름이나 PackageId 접두어, 버전 차이, 동일 파일 개수는 인계 조건이 아니다. 열 이름을 기준으로 6열·9열 기록을 정규화하며 미래의 추가 열도 허용한다. 여러 기록은 실제 현재 해시와 대조한다. 손상된 행은 진단에 남기고 정식 배포 증거로 보완한다.

공식 배포 목록은 GitHub 자산 SHA-256, ZIP 내부 매니페스트, 실제 payload 해시·크기를 대조해 만든다. `Build-UpgradeCatalog.py`는 특정 버전 쌍을 코드에 넣지 않고 공개 릴리스 목록 전체를 처리한다. 현재 목록은 v0.6.2-hotfix부터 v0.86까지 공개 21개, 중복 제거 후 9,566개 식별 항목이다. 이후 릴리스에서는 같은 도구로 목록을 다시 생성한다. 파일명만으로 덮어쓰지 않는다.

소유권이 검증된 생성 파일은 새 파일로 교체한다. 메뉴·폰트·번역·보조 파일에 동일한 소유권 정책을 적용한다. 현재 내용이 게임 업데이트나 모드로 달라졌다면 기존 구조 기반 적용기를 사용한다. CM 공유 파일은 통째로 대체하지 않고 현재 파일에서 필요한 변경만 적용한다. 아카이브는 기존 동적 패처를 유지한다.

오래된 패치 자체가 메뉴 구조를 바꾸어 현재 파일의 직접 변환이 실패한 경우, 실제 현재 파일이 이전 기록의 적용 결과와 정확히 일치하고 원본 백업의 해시·크기도 검증될 때만 그 원본에서 새 후보를 만든다. 모드나 게임 업데이트로 달라진 파일에는 이 경로를 사용하지 않는다. 원본 후보 역시 구조 검증을 통과해야 한다.

폐기 경로는 과거 목록과 최신 관리 목록의 차이로 계산한다. 소유권이 검증된 생성 파일만 삭제하며, 수정 파일은 검증된 백업이 있을 때 복원한다. 외부 변경 또는 CM 소유 파일은 보존한다. 실제 공개 이력에는 최신 목록에서 사라진 경로가 없어, 폐기 경로는 별도 축소 매니페스트로 검증한다.

`UpgradeTransaction`은 후보 검증 후 현재 파일·설치 기록을 백업하고 영속 저널을 만든다. 적용 중 실패하면 작업 직전 파일과 기록을 복원한다. 강제 종료 뒤에도 같은 저널을 검증하고 복구한다. 후보 검사 이후 해시 변화, CM 상태 변화, 동시 설치 잠금, 복구 중 예상 외 파일 변화는 차단한다. 기존 게임 업데이트/CM 중단 저널도 먼저 복구하며 재적용 자체는 후보 단계에 통합했다.

설치 기록 schema_version 2에 버전, 소유권 증거 정책, 적용 결과, 원본 백업과 제거 시 복원 정책을 남긴다. 현재 파일이 이전 적용 결과와 일치할 때만 기존 원본 백업을 인계한다. 게임 업데이트로 달라진 파일에는 구버전 원본을 사용하지 않는다.

원본 백업을 잃은 패치 상태에서는 한글 메뉴만 남기고 폰트를 삭제하는 불완전 제거를 방지하기 위해 전체 업그레이드 직전 상태를 백업한다. `restore_policy=PRE_UPGRADE`로 기록하고 안내한다. 이것은 순정 파일을 재구성했다는 의미가 아니다. 정식 배포 목록은 소유권 증거이지, 사라진 사용자 원본의 대체물이 아니다.

일반·VR 업데이트는 기존 부모 프로세스 종료 대기를 거친 뒤 같은 설치 엔진을 호출한다. Steam 인수는 각각 `-applaunch 1066890 -novr -lang=Korean -looseloadtext`, `-applaunch 1066890 -forcevr -lang=Korean -looseloadtext`로 유지했다. 설치 화면과 업데이트 후 실행도 공통 실행 정책을 사용한다.

- `Test-CommonUpgrade.py`: 공개 0.86 실패 재현, 대표 구버전 직접 업그레이드, 기록 변형, 재설치·제거, 폐기 경로, 충돌, 롤백·중단, CM, 부모 프로세스 대기.

## 범위 제한

공식 배포 식별 21개와 모든 버전의 실제 게임 실행은 다르다. 설치 방식이 달라진 대표 버전을 골라 자동 검증한다. v0.6.2-hotfix 이전 비공개·로컬 배포물은 정식 해시 목록으로 입증하지 못한다. 정상 설치 기록과 실제 파일이 일치하면 공통 기록 경로로 인계할 수 있지만 미확인 배포 전체를 검증했다고 주장하지 않는다.

복사본 검증은 실제 게임 실행을 하지 않는다. 실제 한글 표출, VR, 멀티플레이, 제보 사용자 PC는 별도 확인 범위이다. 파일 구조가 실제로 손상되거나 소유권을 입증할 수 없는 외부 파일을 무조건 덮어쓰지는 않는다.
